# Lifting from rustc's MIR

Status: prototype; commonware-codec's varint is verified through it with
its laws and proofs unchanged. The appendix (§20) is the normative reading;
it joins SEMANTICS.md at the next acceptance of the specification locks
(SEMANTICS.md is part of every `SPEC.lock`'s `semantics` hash). This note
records the decision, the design, the measurements and the plan to retire
the source lift's reading of bodies.

## 1. Why

The source lift (`front/src/lift.rs`, `lift_open.rs`, templates, prelude)
re-implements Rust's surface semantics on source text: `?`, `map_err`,
closures, operator traits, `for` loops and iterators, `impl Iterator`,
`macro_rules!`, `T::SIZE` and `const` assertions, signed integers, state
passing. Each new crate brings new surface features, so the trusted
reading grows with every port (4k budget, 6.4k and climbing after the MMR
and verifier tracks). rustc already gives the meaning of all of that in a
small, typed, monomorphized form — MIR — and rustc is already trusted (it
compiles the code). Reading MIR moves the trust from "our reading of Rust"
to "our reading of a small, stable set of MIR constructs".

## 2. Getting MIR out of rustc: options and decision

| | rustc_public (Stable MIR) driver | Charon (ULLBC/LLBC JSON) | custom driver on `rustc_middle` | `rustc --emit=mir` text |
| --- | --- | --- | --- | --- |
| toolchain | nightly + rustc-dev, pinned | its own pinned nightly, external project (Aeneas) | nightly + rustc-dev | the stable compiler itself |
| API stability | designed to be stable-ish; small surface | JSON schema tied to Charon's version | none (changes every nightly) | text format explicitly unstable, no types of temporaries' projections, no spans without `-Z` |
| monomorphization | `Instance::resolve` + `Instance::body()` (monomorphized, constants evaluated) | generic bodies; monomorphization is Charon's or ours | ours | generic bodies |
| structured control flow | CFG (we structure) | LLBC is already structured — but that structuring is Charon's code, trusted | CFG | CFG |
| extra trust | a ~0.8k-line printer | Charon (~tens of k lines of Rust + OCaml consumers) | the printer, rewritten per nightly | a text parser of an unstable format |
| fidelity to the build | same MIR building as the stable release when pinned to its nightly | Charon's nightly, not the build's | same as rustc_public | exact (same compiler) but generic and weakly typed |

**Decision: a small rustc driver on `rustc_public`**, pinned to the
nightly of the stable release the monorepo builds with
(`nightly-2026-06-21` = `1.98.0-nightly` for stable `1.98.1`), whose output
is **checked in** (`codec/sandblaster/varint/varint.sbmir`) like the other
verified inputs. Reasons:

* rustc is the only thing that can say what Rust means; `rustc_public` is
  the part of it meant for tools, gives monomorphized instances with
  constants evaluated, and exposes exactly the MIR constructs we read.
* Charon's structuring and its schema would be new trusted code the size of
  the problem we are removing; we structure ourselves where structure only
  decides shape (post-dominators, `cfg.rs`, untrusted) and read edges
  exactly.
* `--emit=mir` text is from the exact compiler but is generic, has no
  types for many temporaries' projections and no stable syntax; parsing it
  would be trusted and fragile.
* The workspace stays on stable: extraction is a separate step
  (`sandblaster/mirx/extract.sh`) whose output is keyed by the sources'
  SHA-256 and the compiler version; a stale file is refused by the build.

**Fidelity** (MIR from a nightly, code generated by stable). Three guards:
(1) the extraction nightly is the nightly of the same release series as
the build's stable compiler (`1.98`), and the build refuses MIR of another
series (`mir::load` compares `rustc -vV`); (2) the MIR constructs read are
the language's core semantics (checked integer arithmetic, control flow,
aggregates, borrows), which are specified by the language and do not vary
between compilers of one release; library code is read from that release's
`core` or through a short list of leaves whose documented meaning is the
subset's builtin; (3) the lift conformance check runs the read functions
in the kernel against the build's own rustc's compilation of the source on
generated inputs, every build. Once `rustc-dev` of the stable toolchain
itself is allowed on the build machines (rustup ships it for stable too,
with `RUSTC_BOOTSTRAP=1`), the driver can be built against the exact
compiler that builds the crate, and guard (1) becomes identity.

**Monomorphization.** The driver instantiates each function of the module
at the impl types of the sealed traits bounding its type parameters (a
local trait whose impls are all local: coherence and privacy make that
set exact), minus the declared unverified types; open traits are read at
their declared instance (`SBMIR_INSTANCE`, SEMANTICS.md §19.6); a
`Buf`/`BufMut` parameter is instantiated at `&[u8]`/`&mut [u8]` and its
trait calls are read as the buffer model whatever the receiver.

**Spans.** Every statement and terminator carries `(at file line col)` of
the user's source (the stub's `OUT_DIR` copy is mapped back to the source
file by its line offset); reading errors name the function and the MIR
instance; laws and proofs refer to functions and types by their Rust paths
and lifted names, exactly as before.

## 3. Design

```
 source ──rustc (pinned nightly)──► sandblaster-mirx ──► m.sbmir (checked in, SHA-256 of sources, rustc version)
                                                             │
 DSL root: #[lift(mir = "m.sbmir")] mod m;                   ▼
   lift (skeleton: items, names, signatures, attachments) + mir::read (bodies) ──► exec subset ──► elaborator ──► kernel
                                                             │
                           lift conformance check: kernel evaluation vs the build's rustc, every build
```

* `mirx` (trusted printer): S-expressions of every reachable instance —
  locals with types and debug names, blocks, statements, terminators,
  callee classification (module function / library function / closure /
  shim / leaf / intrinsic / diverging), ADT definitions with variants,
  discriminants and field types, constants destructured by rustc.
* `front/src/mir/ir.rs`, `sexp.rs` (untrusted): parsing.
* `front/src/mir/cfg.rs` (untrusted): reachability, back edges and natural
  loops, post-dominators ignoring diverging paths, liveness. It only
  decides shape: the reading follows every edge whatever it says.
* `front/src/mir/read.rs` (trusted): the reading of `docs/mir-lift.md` §20.2 —
  a symbolic walk of the CFG with values that are pure expressions or
  known constructors; library calls and closures inlined with their
  returns continuing the caller; module functions called by name with state
  passing; `while` for test-only loops, tail-recursive helpers otherwise,
  loop attachments placed as the source lift places them.
* `front/src/mir/mod.rs` (trusted names): MIR types and constructors to the
  subset's (`UInt<u16>` → `UInt__u16`, `Result` → the lift prelude's,
  host models by name), lifted names of module instances, and the checks
  of `load` (format version, module, overflow checks, source hashes,
  compiler release).
* `lift.rs`: `#[lift(mir = ..)]` loads the file; for every lifted exec
  function of the module it skips the source reading of the body, checks
  the signature against the MIR (parameter count, state parameters =
  `&mut` parameters), reads the loop attachments with the MIR's locals
  typed, and takes the body and helpers from `mir::read`.

## 4. What works

* commonware-codec's varint, all 63 lifted functions at u16/u32/u64 and
  i16/i32/i64, read from MIR: `write` (a `while` with its invariant and
  `after_loop!` placed as before), `read` (`?` and `map_err` inlined from
  core's own MIR and collapsed by known constructors to one `match` per
  byte, the decoder loop as `read__uN__loop0` with the attachment's
  measure and summary), `Decoder::feed` (`checked_sub().unwrap()` inlined
  from core: an `unreachable!()` under `max_bits < bits_read`),
  `size` (`div_ceil`, `max` as builtins, `leading_zeros` via `ctlz`),
  ZigZag (signed shifts, negation with its overflow check as `iN_neg`'s
  precondition), the `Read`/`Write`/`EncodeSize` impls and `From` impls.
* **LAWS.rs and PROOF.rs unchanged** (0 of 3,865 proof lines adapted):
  48 laws, 21,247 obligations, 0 failed.
* A misreading is caught: reading one constant of `write`'s MIR wrong
  (`len += 2` for `len += 1`) makes the laws fail (see §5).
* `tests/mir.rs`: each construct on hand-written MIR with negative twins
  (signed checked arithmetic, drop glue, calls not extracted, `Len`,
  unknown forms, a non-`&mut` state, another module or format version,
  MIR without overflow checks, a stale source, a missing source), and the
  codec extraction read end to end by the front end.

The MMR survey (`front/examples/mir_survey.rs` over the extraction of
`merkle::{position, location, mmr}` at `Family = mmr::Family`): 74 of 85
extracted roots read; of the 11 others, 6 are codec `Read`/`Write` impls the
MMR declarations leave out (`unverified_impls`), 2 build the host model
`Error<F>`, and 3 are real gaps (an `assert_eq!` payload, `fmt::Arguments`
in an `assert!` message, one unsizing form). Run in place through the
lift (dev copy, removed), the MMR front end stops at 23 errors in six
kinds: attachments that name a local shadowing a parameter (`let size =
*size;` reads as `size_2`), loop helpers of `&mut self` methods, the
generic host model `Error<F>`, `PeakIterator`'s `Iterator` impl and
fields, assertion messages, and comparisons in attachments over
`Position`. The MMR proofs were not run through the MIR path.

## 6. Plan to replace the source lift

1. **Now** (this prototype): bodies from MIR for module-mode crates;
   the source lift keeps the skeleton and the ghost language.
2. **MMR and verifier** (in place): multi-module extraction (done in the
   driver: `SBMIR_MODULE="a,b"`, open-trait instances `SBMIR_INSTANCE`),
   leaves for core's range iterators (the lift prelude's `RangeU64` model:
   `Range::next`'s MIR goes through `mem::replace` and `Step`), `for`
   loops as helpers with the iterator named `iter` (rustc's own debug name
   for the desugared loop), operator-trait calls as calls of the lifted
   impls by name (`Position::add__u64`), `impl Iterator` returns (the
   concrete type is in the MIR), open-trait associated constants (already
   evaluated by rustc). Then the conformance check of in-place modules
   runs on MIR-read bodies like on module mode.
3. **Delete the source lift's body reading** once every exec module reads
   MIR, in this order (each deletion is dead code at that point):
   `lift_open.rs`'s loop and iterator desugaring (`while_helper`,
   `for_helper`, range and `once` iterators, `impl Iterator` returns),
   closures and combinator templates (`combinators.rs`,
   `instantiate_template`, `closure_call`), operator/conversion/`Deref`
   rewriting of exec bodies, assertion macros, `?`/`map_err`/`unwrap`/
   `checked_*().unwrap()` rewrites and `&a[..=j]`, exec state passing
   (`state_rewrite`, `wrap_state_ret`, buffer calls), signed-integer
   rewriting of exec code (ghost code keeps `int_of_iN`), `T::SIZE` and
   `const` evaluation, the prelude iterators and `Ordering` helpers.
   About 2.3k of the 6.8k code lines.
4. **Skeleton from MIR**: generate the lifted items (struct and enum
   declarations from the `adt-def`s, signatures from the instances' MIR
   signatures with state passing from `&mut`, the sealed families from the
   extraction's instantiation), so macro expansion, inline-module
   flattening, sealed-trait and open-trait monomorphization of exec items
   leave the source lift (another ≈ 2k lines). What remains of `lift.rs`
   is the ghost language's monomorphization over the families (laws and
   proofs), which is TCB item 6 anyway.
5. **Shrink the reader's trust**: the structuring (joins, loop forms,
   carried values) is where a bug would change meaning (one was found and
   fixed while prototyping: a value snapshot restored a variable after an
   in-place write). Replace it by a checked step: a literal CPS reading
   (every block a function, no carrying) that is obviously MIR, plus a
   kernel-checked equality between it and the structured reading, so only
   the literal reading (~0.5k lines) stays trusted.

## Appendix: `docs/mir-lift.md` §20 (text pending the next lock acceptance)

`SEMANTICS.md` is part of every `SPEC.lock`'s `semantics` hash, so this
section joins it when the locks are next accepted (as DESIGN.md §2.1 does
for `#[lift(opt)]`); until then it is normative from here.

#### 20. Bodies read from rustc's MIR (`#[lift(mir = "m.sbmir", ..)]`)

A lifted module declared with `mir = "file.sbmir"` keeps §19's item
skeleton (which items exist, their lifted names and signatures, state
passing, the sealed-trait families, the struct and enum declarations, the
attachments) and reads **every function body** from rustc's MIR instead of
the surface syntax (`crate::mir`; DESIGN.md §1.1 item 8, §2.1). The source
lift's body rewrites (§19.1's `?`/`map_err`/`unwrap`/`checked_*().unwrap()`,
§19.7's templates and closures, §19.8's operator impls, §19.9's loop and
iterator desugaring and assertion macros, macro expansion inside bodies,
`T::SIZE`, `const` asserts) are not used for such a module: rustc has done
all of that before MIR exists.

#### 20.1 The extraction

`sandblaster/mirx` is a rustc driver (`rustc_public`, the nightly of the
stable release the workspace builds with, pinned in its
`rust-toolchain.toml`) run as cargo's `RUSTC_WORKSPACE_WRAPPER` by
`sandblaster/mirx/extract.sh`. For the crate's library it instantiates each
function of the module at the impl types of the sealed traits that bound its
type parameters (minus the declared unverified types), takes rustc's
monomorphized MIR (`Instance::body`: optimized MIR, constants evaluated,
overflow checks as the build's profile has them), follows the calls into
library functions and closures (their MIR too), and prints it as
S-expressions with the SHA-256 of every source file it came from and the
compiler's version. A parameter bounded by `Buf`/`BufMut` is instantiated
at `&[u8]`/`&mut [u8]`; the reading never looks at that type (it reads the
buffer traits' calls as §19.1's buffer model whatever the receiver). The
file is checked in; the build refuses it when a source's hash differs,
when it was extracted without overflow checks, or when the build's rustc
is of another release (`1.98.x` against `1.98.0-nightly`).

#### 20.2 The reading (`crate::mir::read`, trusted)

The reading walks the control-flow graph from the entry block and follows
its edges exactly. Where two paths rejoin is taken from post-dominators
(ignoring paths that return or cannot continue); that only decides the
shape of the output.

| MIR | subset |
| --- | --- |
| `StorageLive`/`StorageDead`, fake reads, place mentions, user type ascriptions, coverage | nothing (no runtime meaning) |
| `x = rv` | `let x = ⟦rv⟧` / `x = ⟦rv⟧`; a pure total value (variable, constant, comparison, bit operation, unsigned cast, constructor of such) is carried instead of bound; before a variable changes, carried values that read it are bound |
| `CheckedAdd/Sub/Mul(a, b)` and the `assert(!overflowed)` that follows | `a + b` (`- *`): the operator's obligation is exactly that the flag is false |
| `Add/Sub/Mul` (no check: library code) | `wrapping_add/sub/mul` |
| `AddUnchecked/..`, `Div`, `Rem` (undefined behavior on overflow / zero) | `+ - * / %` with their obligations |
| `Shl`/`Shr` (the amount masked) | `<<`/`>>`, whose obligation (amount below the width) is where the two agree |
| `assert(c)` | `if !c { unreachable!() }` — except when the next operation's own obligation is `c` word for word: `i < N` before an index of an `[T; N]` by `i`, `s < w` before a shift of a `w`-bit value by `s`, `d == 0` false before a division or remainder by `d`, `x == MIN` false before a signed negation of `x` |
| `assume(c)` | `if !c { unreachable!() }` |
| `switchInt(discriminant(x))` | `match x { V(..) => .. }` over the variants, binding the fields a later `(x as V).i` reads; a constructor known on the path picks its arm |
| `switchInt(b)` on a `bool`/integer | `if`/`match` with literal patterns |
| `&x`, `&raw`/fake borrows | the value of `x` (unchanged while the shared borrow lives: rustc's borrow checker) / nothing |
| `&mut x`, `&mut *r` | `x` as a place: a write through the borrow assigns `x` |
| call of a module function | a call by its lifted name; `&mut` arguments are passed by value and assigned from the returned states (§19.1) |
| call of a library function or closure | its MIR, inlined (parameters bound to the arguments, its return continuing the caller) |
| `BufMut::put_u8/put_slice`, `Buf::try_get_u8` | the buffer model `crate::__lift_model::*` on the buffer state |
| `<[T; N] as Index<RangeToInclusive / RangeTo / RangeFrom / Range>>::index(&a, r)` | `&a[..j + 1]`, `&a[..j]`, `&a[i..]`, `&a[i..j]` (both panic exactly when the subset's obligations fail) |
| `Ord::max/min` of unsigned integers, `uN::div_ceil` | the builtins `max`, `min`, `div_ceil` |
| `ctlz` (`leading_zeros`) | the builtin `leading_zeros` |
| a function returning `!` (`unwrap_failed`, panics) | `unreachable!()` |
| `drop` of a value without drop glue | nothing; with drop glue refused |
| a loop whose header only computes a test and whose only exit is that test | `while test { .. }` with §19.9's attachment placement |
| any other loop | a tail-recursive helper `f__loopK` over the variables live at its header (in their order of first use, states last) plus those its attachment names, with the attachment's `invariant`/`decreases`/`ensures`/`at_start!` |
| signed operations | §19.3's two's complement reading |
| everything else (raw pointers, function pointers, `Len`, `Transmute`, runtime checks other than overflow checks, a call rustc did not let the extractor follow, loops in library code) | refused |

The lift's signature is checked against rustc's: the parameter count, and
that exactly the lift's state parameters are `&mut` in the MIR. A
parameter bound by `_` is read only when zero-sized. Loops are numbered in
source order for attachments (`loop_nr = k`).

#### 20.3 What is trusted

The reading (`crate::mir::read`), the type and constructor names
(`crate::mir::ModuleNames`), the three builtin leaves and the index leaves,
and the printer `sandblaster-mirx` (it transcribes rustc's data). rustc is
trusted as it already is (it compiles the code); the fidelity argument is
that the MIR comes from the same release as the compiler that builds the
crate, and the lift conformance check (§1.1 item 8) compares every read
function with that compiler's build of the source on generated inputs. The
S-expression parser, the control-flow analyses (`cfg.rs`) and the matching
of lifted names to MIR instances are not trusted (a wrong one is a refusal,
a name error or a type error).
