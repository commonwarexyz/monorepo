Batching the Subgroup Check

Three randomized strategies for verifying that a batch of untrusted BLS12-381 points lies in the prime-order subgroup — what each buys per round, why one third is the barrier for a single combination, and how to buy m combinations for the price of one pass.

curve BLS12-381 G1 target ε ≤ 2⁻¹²⁸ measurements: 18-core Apple Silicon

1 · Setting

Let E/𝔽p be the BLS12-381 curve, with |E(𝔽p)| = h·r for a 255-bit prime r and cofactor

h = 3 · (11 · 10177 · 859267 · 52437899)² ≈ 2¹²⁶.

Since gcd(h, r) = 1, the curve group splits as E(𝔽p) ≅ H ⊕ 𝔾₁, where 𝔾₁ is the prime-order subgroup and H the subgroup of order h. Every on-curve point decomposes uniquely as P = G + T with G ∈ 𝔾₁, T ∈ H; write π(P) = T for the projection. π is a group homomorphism, and P ∈ 𝔾₁ ⟺ π(P) = 0.

Decoding an untrusted point validates its encoding and the curve equation but says nothing about π(P); consuming a point with π(P) ≠ 0 in a pairing or scalar multiplication opens small-subgroup attacks. The exact membership test — Scott’s endomorphism check (eprint 2021/1130, blst’s blst_p1_in_g1) — costs about 22 µs; a batch-affine point addition costs about 0.15 µs. This ≈150 : 1 exchange rate drives every design decision below: strategies are judged by how many exact checks and how many passes over the points they spend.

The verifier’s game. The adversary submits on-curve P₁, …, Pn. The verifier tosses private coins, forms a few combinations of the points, and exact-checks only those. The soundness error is

ε  =  max∃i : π(Pi) ≠ 0  Pr[ verifier accepts ],

with target ε ≤ 2⁻¹²⁸. Because π is linear, π(Σ ciPi) = Σ ciTi: every strategy is a question about when random combinations of the cofactor parts vanish in H.

2 · The one-third barrier

Lemma 1 (trit combination). Let H be a finite abelian group of odd order, let c₁, …, cn be i.i.d. uniform on {0, 1, 2} ⊂ ℤ, and let T₁, …, Tn ∈ H, not all zero. Then Pr[Σi ciTi = 0] ≤ 1/3.

Proof. Fix j with Tj ≠ 0 and define the H-valued random variable U = −Σi≠j ciTi. As a function of {ci}i≠j alone, U is independent of cj, and

Σi ciTi = 0  ⟺  cjTj = U.

Claim: the map φ : {0, 1, 2} → H, φ(a) = aTj, is injective. Let d = ord(Tj). By Lagrange’s theorem d divides |H|, and a divisor of an odd number is odd, so d is odd. Tj ≠ 0 means Tj is not the identity, so d ≠ 1. The only integer strictly between 1 and 3 is 2, which is even — excluded. Hence d ≥ 3. Now if φ(a) = φ(b) with a > b, then (a − b)Tj = 0, so d | (a − b) — contradicting 0 < a − b ≤ 2 < d. (This step is exactly where an even group order would break the lemma: it admits d = 2, and then φ(0) = φ(2) = 0 — only two distinct values, and the bound degrades to 2/3.)

Injectivity gives |φ⁻¹(u)| ≤ 1 for every u ∈ H. Since cj is uniform and independent of U, for every u in the support of U,

Pr[ cjTj = U | U = u ]  =  Pr[ cj ∈ φ⁻¹(u) ]  =  |φ⁻¹(u)| / 3  ≤  1/3,

and averaging over the law of U,

Pr[ Σi ciTi = 0 ]  =  𝔼U Pr[ cjTj = U | U ]  ≤  1/3. ∎

Five remarks a reviewer should check:

  1. The barrier is real, not an artifact of trits. 3 | h, so H contains T of order 3. Against the pair (T, −T), a single combination with coefficients from any distribution 𝒟 escapes iff c₁ ≡ c₂ (mod 3) — the mod-3 collision probability of 𝒟, which is ≥ 1/3 for every distribution (Σp² ≥ 1/3, equality iff uniform). No single combination beats 1/3; larger coefficients only cost more.
  2. Budget. t independent combinations give ε ≤ 3⁻ᵗ. 3⁻⁸¹ = 2⁻¹²⁸·³⁸ meets the target; 3⁻⁸⁰ = 2⁻¹²⁶·⁸ does not. Every strategy below is a way of purchasing 81 combinations; they differ only in the price.
  3. Exact uniformity is load-bearing. The margin is 0.38 bits. Sampling a trit as byte % 3 puts mass 86/256 on one residue, and a lone planted bad point then escapes each combination with probability 86/256, giving (86/256)⁸¹ = 2⁻¹²⁷·⁵ — below target. The implementation rejection-samples bytes < 3⁵ = 243, each accepted byte yielding five exact trits.
  4. Coins are the verifier’s private randomness. As in batched signature verification, the coefficients must be unpredictable to whoever chose the points; they are drawn fresh per batch and never reused.
  5. Adversarially correlated points are priced in — quantifier order does the work. The lemma reads ∀(T₁,…,Tn) fixed, then probability over the coins alone: the adversary may choose Tj as any function of the other Ti before the coins are sampled, and the proof is insensitive to it — U is a function of the other coins and of constants, and the conditional bound Pr[cjTj = U | U = u] ≤ 1/3 holds uniformly for every value u, whatever U’s distribution. The natural objection — “with small weights, ΣciTi is structured and not independent of the Ti” — is true and harmless: no such independence is used. The worst case realizes it: T₂ = −T₁ escapes iff c₁ = c₂, exactly 1/3, meeting the bound with equality. Nor would large weights help: by remark (i), even full-width coefficients act mod 3 in an order-3 component and leave the pair a ≥ 1/3 escape. The model’s real requirements are the ones in remark (iv): fresh, private, unpredictable coins — the bound does not survive coin reuse or a predictable source.
A

One combination per round

previous implementation

The direct construction: 81 rounds, each drawing fresh trits and exact-checking Q = Σ ciPi. The combination is a 2-bit multi-scalar multiplication, and Pippenger’s algorithm already evaluates it by grouping: skip the ci = 0 points, sum the two coefficient classes B₁, B₂ with batch-affine additions, return Q = B₁ + 2B₂.

Price: soundness needs 81 combinations and A evaluates one per pass, so it pays 81 full passes over the n points (≈126 ns/point in blst) and 81 exact checks. At n = 6000 that is 63 ms serial — a 2× win over per-point checking, entirely from the exact-check count dropping from n to 81. The passes are now the bottleneck: each extracts only log₂3 ≈ 1.58 bits.

B

Random bucketing

celo/zexe · rejected

The 2019 zexe construction (celo/zexe PR #4): draw a uniform bucket map β : [n] → [B], and exact-check every bucket sum Sb = Σβ(i)=b Pi.

Lemma 2 (bucketing). If some Tj ≠ 0, then Pr[∀b : π(Sb) = 0] ≤ 1/B.

Proof. Fix j with Tj ≠ 0 and condition on the buckets of all other points; let σb be the torsion already in bucket b. If j lands in b, acceptance requires σb + Tj = 0 and σb′ = 0 for all b′ ≠ b. Were two buckets b₁ ≠ b₂ both admissible, the first condition at b₂ and the second at b₁ force −Tj = σb₂ = 0, a contradiction. So at most one admissible bucket exists, and β(j) is uniform over B. ∎

The bound is exact for the cancelling pair (T, −T): same bucket ⟺ everything cancels ⟺ escape, probability 1/B. So one pass now extracts log₂B bits — more than A’s 1.58 — because keeping B separate constraints refuses to collapse them into one combination. Rounds: ⌈128/log₂B⌉, e.g. 32 at B = 16.

Price: the constraints must each be checked. That is rounds × B exact checks — 512 at B = 16, an 11.3 ms serial floor independent of n, against A’s 1.8 ms. Implemented naively (one batch-add call per bucket) it also pays per-bucket inversion chains. Measured: slower than A at n = 1000 (15.9 vs 12.1 ms serial) and only 1.35× ahead at n = 6000. The information per round went up; the price per round went up faster.

C

m parallel combinations, one pass

shipping

Draw for each point a coefficient vector vi = (c1,i, …, cm,i) uniform on {0, 1, 2}m, and exact-check the m combinations Qj = Σi cj,iPi.

Theorem (round soundness). If some Ti ≠ 0, then Pr[Q₁, …, Qm ∈ 𝔾₁] ≤ 3⁻ᵐ.

Proof. The event “π(Qj) = 0” is a function of the j-th coordinates alone, and coordinates are disjoint fresh trits, so the m events are independent. Each has probability ≤ 1/3 by Lemma 1. ∎

With r = ⌈81/m⌉ rounds, ε ≤ 3−rm ≤ 3⁻⁸¹. The worst case matches the bound: the pair (T, −T) escapes a round iff the two points drew identical vectors — coordinate differences lie in {−2, …, 2} and are annihilated only by 0 — probability exactly 3⁻ᵐ.

Evaluating m combinations for one pass

The construction is worthwhile only if m combinations cost roughly one. Three observations make that true:

  1. Grouping is free. Read vi as a base-3 index into 3m classes. Points sharing a vector contribute identical coefficients to every combination, so first sum each class: still n additions total, independent of 3m — each point lands in exactly one class.
  2. The additions share their inversions. Affine addition needs λ = Δy/Δx, an inversion each. Instead, a pass pairs up the remaining points of every class and Montgomery-batches all denominators: prefix products, one real inversion, back-substitution — 3 multiplications per inverse, ≈6 multiplications per point addition, ⌈log₂(max class)⌉ passes. Measured 146–178 ns/point, flat from 27 to 243 classes. Adversarial edge cases are handled explicitly: planted (P, −P) pairs collapse to the identity mid-tree; equal-x pairs are classified as cancellation or doubling; and denominators never vanish because h·r is odd — the curve has no 2-torsion, so y ≠ 0 on-curve.
  3. Recombination is deterministic. With digitj(v) the j-th base-3 digit,
    Qj = Σdigitj(v)=1 Sv  +  2·Σdigitj(v)=2 Sv,
    a combine over 2·3m−1 class sums per output — trivial next to the pass.
The unsound shortcut Replacing the m checks by one re-randomized check Σv rvSv collapses the round back to the barrier: the pair placed in classes v ≠ v′ escapes iff rv ≡ rv′, a collision event of probability ≥ 1/3 by remark (i). The m separate checks with deterministic digit weights — all randomness in the vector assignment — are precisely what preserve the product structure 3⁻ᵐ.

Where C sits relative to A and B

C generalizes A: at m = 1 the class sums are Pippenger’s coefficient buckets and the digit combine is B₁ + 2B₂ — strategy A exactly. C dominates B: set B = 3ᵐ and a B-round and a C-round have the same accumulation and the same escape bound 3⁻ᵐ, but B exact-checks 3ᵐ sums where C checks m recombinations. C’s check total stays at r·m ≈ 81 — the Lemma-1 budget, i.e. the minimum any strategy in this family pays — for every m.

The combine grows as 3ᵐ, capping useful width: a cost model picks m per batch (m = 3 at n = 1000, m = 4 at n = 6000) and falls back to per-point checking below n ≈ 120. The model’s constants steer only speed — any (m, r) with rm ≥ 81 is sound.

3 · Notes for review

  1. Odd cofactor is a precondition of the trit instantiation, not of the construction. Lemma 1 needs ord(T) ≥ 3: an order-2 part has 2T = 0, so trit coefficients escape with probability 2/3 per combination, and BLS12-377 𝔾₁ (2⁹² | h) cannot use the scheme as-is. Switching to {0, 1} coefficient vectors restores it for even cofactors — cT ∈ {0, T} is injective on {0, 1} for any T ≠ 0, giving ≤ 1/2 per combination, 2ᵐ buckets, and 128 combinations total instead of 81.
  2. Relation to the state of the art. The current literature reference is Koshelev–El Housni–Fotiadis (eprint 2025/1311): a per-point Tate-pairing/power-residue prefilter removes the 3- and 11-torsion so that a few rounds of 13-bit-coefficient MSMs suffice. They state the same 1/3 barrier and analyze the same multi-round small-coefficient route, but their cost model charges one full MSM per round — and by their own benchmarks the end-to-end method is slower than naive per-point checking on unmodified BLS12-381 (the prefilter dominates; their remedy is generating new curves). They name batch-affine additions with Montgomery inversion as future work; the cross-round vector-bucketing used here does not appear. The honest novelty claim is therefore scoped: every ingredient is classical (small-exponent batch testing, multi-product bucketing, Montgomery inversion), and what appears new is the composition for this problem — one accumulation pass serving all m combinations, which removes exactly the cost their model assumes and makes the no-prefilter route win on the unmodified curve at a stronger 2⁻¹²⁸ target.
  3. The combine wiring is soundness-critical and invisible to black-box tests. A bug that reuses one digit position for every output (a stuck divisor) silently degrades a round from 3⁻ᵐ to 3⁻¹ — ε goes from 2⁻¹²⁸ to ≈2⁻⁴³ — while valid batches still verify and bad batches still mostly reject. The test suite plants a single bad point at chosen class indices: at v = 0 the round must accept (every digit 0); at v = 3ʲ and v = 2·3ʲ combination j alone must reject, isolating each digit position and weight deterministically.
  4. Assurance. The accumulator is differential-tested against naive group addition over mixed valid / off-subgroup / identity / negated / duplicated inputs, with deterministic tests for each special-case branch; adversarial batch tests cover the cancelling pair and mass-duplicated bad points. The only new unsafe code is thin per-call FFI wrappers over blst field ops; all pass scheduling is safe Rust.
  5. Provenance. Shipped as bls12381::primitives::subgroup::batch_in_g1 in commonware PR #4528, ALPHA-gated pending review; the in-repo comparison lives at cryptography/BATCHED_SUBGROUP.md. Strategy B reference: celo/zexe PR #4 (2019).
