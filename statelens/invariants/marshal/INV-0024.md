## Statement
When certifying a notarized proposal in inline mode, the replica shall return a positive result
only after the block matching the notarized digest is durably stored, without requiring a local
application-verification verdict for that proposal.

## Rationale
The notarizing quorum supplies the validity evidence in inline mode. A replica which missed the
proposal or stopped local verification still needs to certify after obtaining and persisting the
block. Conversely, a readable but unsynced block is insufficient to authorize finalization.

## Evidence
`consensus/src/marshal/standard/inline.rs:515-520@55cd57fd2137` separates the application verdict
used for notarization from the durability gate used for certification, including when local
verification is cancelled after nullification. `Inline::certify` consumes an applicable durability
gate or fetches the notarized block and waits for durable storage. An absent, dropped, or
inapplicable gate takes this recovery path rather than supplying a negative application verdict.

## Preconditions / assumptions
The replica is honest and consensus supplies a valid notarization. A local rejection may concern
a different proposal header for the same round and digest, so it is not a substitute for the
notarization's validity evidence. This statement does not guarantee completion when the block is
unavailable or the request is cancelled. An actual storage failure terminates use of the store;
runtime shutdown may abandon the request.

## Observation hints
Observe `Inline::verify`'s durability task and `Inline::certify` in
`consensus/src/marshal/standard/inline.rs`, plus proposal gates in
`consensus/src/marshal/application/gates.rs`. Correlate durability with the exact round and digest.
Include certification after restart, after a dropped verification receiver, and without a local
verification call. INV-0019 separately covers securing a local copy before suppressing a fetch.
