title: Deferred leader recovery preserves the previously persisted proposal

## Statement
When recovering as proposer for a round with a previously persisted proposal in deferred mode,
the replica shall publish only that proposal's digest, and only if its embedded context matches
the recovered consensus context or it is the declared parent at the current epoch's last height.

## Rationale
The pre-crash proposal may have reached peers even when the replica's notarize vote did not reach
its consensus journal. Building a replacement can make an honest leader equivocate. Reusing the
old block under an incompatible recovered context is also unsafe, so recovery may have to abstain.

## Evidence
`standard/deferred.rs:518` describes the crash window and identifies the stored block as the only
proposal that can be broadcast for that round. `Deferred::propose` looks up that block before
calling the application, re-stages it only after the context or boundary-parent check, and returns
without a proposal when the check fails.

## Preconditions / assumptions
The replica is honest, its durable storage survives the restart, and the persisted proposal is
still retained for the recovered round. The boundary exception requires both the stored digest to
equal the recovered context's parent digest and its height to equal the current epoch's last
height. Silence followed by consensus timeout is permitted; this is not a promise to propose.

## Observation hints
Observe the recovered block returned by `get_verified` and the digest published by
`Deferred::propose` in `consensus/src/marshal/standard/deferred.rs`. Include the stored pre-restart
digest in observations rather than deriving the expected value from the newly staged proposal.
