## Statement
When positively certifying an externally proposed new block in coding mode, the replica shall
have obtained the complete block matching the notarized commitment, verified its epoch, embedded
context, and direct parent linkage at the next height against the expected parent commitment,
obtained a positive application-verification result, and completed durable storage of the block.

## Rationale
A coding notarization establishes shard availability and proposal-context agreement rather than
full block validity. Neither a verified shard nor a successful reconstruction is enough to
authorize finalization. Certification must also establish valid ancestry, application acceptance,
and persistence of the complete block.

## Evidence
`Marshaled::deferred_verify` obtains the block and parent and calls `validate_block` before
application verification. `validate_block` in `consensus/src/marshal/coding/validation.rs` checks
both commitments, epoch membership, parent digest and contiguous height, context hash, and
embedded-context equality. `consensus/src/marshal/coding/marshaled.rs:468-470@55cd57fd2137`
explicitly requires both a positive application verdict and durability before publishing a
positive certification gate result. Recovery certification uses the same deferred verification
with the block's embedded context.

## Preconditions / assumptions
The replica is honest and consensus supplies a valid notarization. A new block excludes a valid
epoch-boundary re-proposal; locally built blocks rely on the application's proposal contract
instead of another verification call. With a surviving verification task, the expected context
is the consensus context it checked; recovery uses the embedded context justified by the
notarizing quorum. The complete block may arrive through reconstruction or certified peer
fetching. Missing shards, missing blocks, cancellation, or shutdown need not produce a verdict;
an actual storage failure is fatal.

## Observation hints
Observe `deferred_verify`, `certify_from_existing_task`, and `certify_from_embedded_context` in
`consensus/src/marshal/coding/marshaled.rs`, plus `resolve` in
`consensus/src/marshal/application/gates.rs`. Track validity and completed sync independently of
cache insertion: candidate storage can run before validation. Nullifying a view does not make a
still-needed deferred certification task or its verification obligations disappear.
