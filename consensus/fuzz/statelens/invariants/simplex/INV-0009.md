## Statement
If the replica receives from a participant a vote identical to a valid vote it already received
from that participant for the same view, and that participant has sent no conflicting vote for
the view, then the replica shall not block that participant.

## Rationale
Issue #2070 shows that repeated copies of one signer's vote reach an honest replica. The
maintainers' answer is that the replica skips them ("we skip duplicates in `batcher`"): a copy
adds no participant to a quorum, so dropping it is enough (INV-0006). Skipping is also the only
safe reaction. Honest replicas send identical copies themselves: on every nullify retry after a
timeout, an honest replica signs and broadcasts its nullify vote for the view again, and all
supported schemes sign deterministically, so the retry is byte-identical to the first copy.
Arbitrary network duplication also produces copies. If the replica blocked the sender of an
identical copy, it would disconnect honest participants during exactly the stalled views where
it needs their nullify votes, and could fall below a quorum of reachable peers. Blocking is
reserved for evidence of misbehavior, such as a second vote of the same kind with a different
proposal or signature, or a nullify vote and a finalize vote for the same view. Repeating a
vote does not erase such evidence, so the property only forbids blocking because of the
repetition itself.

## Evidence
Issue #2070 ("panic if there are several votes from one signer"): in a Twins test, two
validators with the same key sent the same signer-3 notarize vote for view 5, and a receiving
replica passed both copies to notarization assembly and panicked on "duplicate signer index: 3".
The reporter noted that "a malicious validator can send two votes and crash all the nodes"; the
maintainer replied that duplicates must be skipped in the batcher
(https://github.com/commonwarexyz/monorepo/issues/2070#issuecomment-3473238479). The issue was
closed by PR #2102 (merge commit 6ca07aba2fee6a37c166885abc94724c77f0b679). This invariant
covers the other wrong reaction to the same input: punishing the sender instead of skipping
the copy.

## Preconditions / assumptions
"Identical" means the same epoch, view, vote kind, signer, proposal (if any) and signature.
"Valid" means the first copy passed, or would pass, signature verification, and the sender is
the participant at the vote's signer index. A "conflicting vote" for the view is a vote of the
same kind with a different proposal or signature, or a nullify vote and a finalize vote for the
view, in either order: each is independent evidence of misbehavior, and blocking the participant
is expected whenever such a vote was received, including when a copy arrives afterwards. The
property holds whether the second copy arrives before or after the replica has formed or
accepted the certificate of that kind for the view. It does not cover a vote for another epoch.

## Observation hints
`Round::add_network` in `consensus/src/simplex/actors/batcher/round.rs:225` returns without
blocking when `previous == vote` (lines 249, 284, 323); after certification the full vote maps
are compacted and `VoteTracker::remember` in `consensus/src/simplex/types.rs:296` must classify
the copy as `Outcome::Duplicate`, not `Outcome::Conflicting`. Honest nullify retries come from
`construct_nullify` in `consensus/src/simplex/actors/voter/actor.rs:469`. The existing test
`duplicate_vote_with_different_attestation_blocks_peer`
(`consensus/src/simplex/actors/batcher/mod.rs:7338`) checks the pre-certificate case. The
batcher blocks cross-kind conflicts before duplicate handling ("nullify after finalize" and
"finalize after nullify" in `Round::add_network`), and returns before recording the second
vote, so a later copy of that vote is blocked again; both are conflicts, not violations. An
assertion can record each (sender, vote) received from the network, plus whether the sender
has sent a conflicting vote for the view, and check that the blocker is never called for a
sender without a conflict whose current vote equals a recorded one.
