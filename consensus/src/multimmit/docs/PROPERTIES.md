# Multimmit properties and evidence

This document is for readers checking the implementation against the counted-views Multimmit
specification. It lists where the code departs from the specification, the properties the code
must keep with their owners and evidence, a crosswalk from each part of the specification to the
code, the test and fuzz campaigns, and what the evidence leaves out.
[`STATE_MACHINE.md`](https://github.com/commonwarexyz/monorepo/blob/main/consensus/src/multimmit/docs/STATE_MACHINE.md)
defines the terms used here (see its
[Terminology](https://github.com/commonwarexyz/monorepo/blob/main/consensus/src/multimmit/docs/STATE_MACHINE.md#terminology))
and states each invariant;
[`DECISIONS.md`](https://github.com/commonwarexyz/monorepo/blob/main/consensus/src/multimmit/docs/DECISIONS.md)
gives the rationale for each deviation and the protocol issues (`I-n`) cited below.

Line numbers (`L223-272`) refer to the first version of the specification's source,
`counted-spec.tex`; `v2 L951-956` refers to its second version, which the code follows (see
`DECISIONS.md`, Scope).

## Assumptions and evidence

Safety assumes `n >= 5f + 1` with at most `f` Byzantine validators and a deterministic
`Automaton::verify`. Liveness also assumes that crashed and unavailable validators count toward
`f`, that messages between correct validators arrive after GST within a delay `delta` whose
`2.5 delta` is below `Tuning::timer_ceiling`, that the measured `delta_hat` is at least
`delta / 2` from some view on, that runtime
and storage keep working, and that the application eventually verifies every correct producer's
block. Outside these assumptions the implementation stays bounded and fails closed, but need not
make progress.

Evidence comes in four kinds:

- **Tests** run a fixed, deterministic scenario or matrix through production code. They catch
  regressions; they do not prove a protocol claim in general.
- **Randomized and fuzz campaigns** let a seed or input bytes choose votes, schedules, or
  artifacts, and compare against an independent reference. They widen coverage but are not proofs.
- **Code inspection** covers claims about types, ownership, and the absence of something, such as
  consensus holding no block bodies.
- **Environment assumptions** are conditions the network, application, or runtime must supply.

## Deviations from the specification

| Specification | Implementation | Consequence | Issue |
|---|---|---|---|
| Leader block `(v, q)` (L303-333, L848-853) | The leader block also carries `c = C(Q')`, the tips-history commitment of its parent V-QC chain; a proposal is valid only if `c` matches. | An L-QC with the record opening `c` pins the tips of every view up to `v - 1`, so it is a verifiable finality certificate. The late final builds `l` from the arriving V-QC's parent, and designation is checked as `H(v, pi, C(parent)) == q`. | I-1 |
| Vote form `(a, ε, F, final)` with anchors and payload paths (L344-427) | The signed subject is `(epoch, view, q, final, F, tips)`: one tip per chain, no anchor, no paths. A reader needs the headers below a tip to interpret a vote, which it needed anyway. | I-5, I-13 |
| Update `k = 1` default for votes for `l` depends on `Q'` (L456-487) | Update zero is always the sender's final tips of `v - 1` (genesis at view one). A reader that has not read that final parks on the sender's vote of tag `v - 1`. | Reading a vote never waits on a V-QC. | I-5, I-A5 |
| Missing updates are requested by sequence number from the sender (L500-511, L1151-1166) | A reader requests a sender's vote of a tag by (sender, tag), only from the sender, which answers with its latest update of the tag naming every chain; that answer bypasses the pending bound for a parked update waiting on it and supersedes the parked updates. | A reader no longer depends on the sender keeping every update; intermediate versions are skipped, which equals delay. | I-D2c1 |
| Finality evidence `R = (v, l, G, P)` (L2688-2709) | A floor is an L-QC plus the record opening its leader block's commitment; the resume index is `sum_i ht(Tips(Q')_i)`. | Acceptance bound (L235-240) | Acceptance additionally requires `h <= finalized + D + N`. | A producer running ahead of finality cannot make validators accept, retain, and endorse headers without bound; a correct producer's blocks are refused only while a validator's final height lags the producer's by more than `D`. | I-PTA2 |
| Acceptance (L223-272) | Full acceptance also requires `verify == true`. | Production (L273-301, L2232; v2 L134-148, L312-327) | Every own block, empty or not, is issued at its slot, `theta` after the previous one, with `theta` the configured constant `Tuning::production_interval`; `Automaton::propose` is answered at once, and an empty body consumes a height. A producer at `theta` stays about a round trip of blocks ahead of its finality and reaches the flow bound only while finality stalls; the bound keeps a faulty or released producer from running ahead. | Flow bound `D` (L2241-2259, v2 L189) | Default `D = 6N`, the second version's sizing (the first had `4N`), ready headers refused by `D` or `D + N` are counted. | A correct producer runs about a round trip of blocks above its final height and a receiver's `h*` and final height trail it by a round trip; `D` must cover both, or the receiver refuses healthy blocks and those chains look silent. | I-PTA8 |
| Durability (implicit, L1116-1150) | The slots of STATE_MACHINE's canonical state are durable before each signature. `lastsent` is volatile: the first update after a restart names every chain and waits `eta`. | Catch-up (the surviving chain is kept forever, L881-896) | Retention keeps `W` views below the newest finalized one. | Own publication duty (not specified) | Own updates and leader blocks stay in the outbox only while their view is within the vote window; older ones are served from resolver custody. | The outbox bound does not grow with `W`. | DECISIONS |
| Initial pre-vote (Alg. 2) | A pre-vote equal to update zero is never sent. | No message carries nothing. | I-A10 |

| Rule (i) (v2 L937-950, L2338) | An uncapped chain with no sign of life for `D_stop` is declared stopped; there is no exemption for a chain at its production bound. | The specification's rule as written. A correct producer at `theta` does not pause, so silence for `D_stop` marks a stopped chain; a finality stall that holds a producer at the flow bound can still be declared, which costs a pin and no safety. | I-PTA4, I-PTA7 |
| Rule (ii) (v2 L951-956, L1064-1066, L1153-1154) | `tquorum` is the first time after entry, before the final vote, at which all but `f` of the `K` chains are capped (sender's sense) or declared; `t_late` after it every chain still neither is declared. Inactive when `K <= f`. | A slow chain is cut about `t_late` after the chains that keep pace cap, at the cost of a pin; the model-safe `t_late` never fires on a chain at pace after GST, and `N theta >= t_late + delta + eta` (D22) keeps the ordering at pace. | I-V3, I-V5, D26 in DECISIONS |
| Rule (v) (L927-935) | First binding tips are compared within the window: a tip at or above `hgt(beta_v) + N` counts as the window's last block. | Healthy views whose producers run past the cap end on count instead of by a spurious split; a split below the window end still fires. | I-A38 |
| Capped (L930-937, L962-975) | Sender side (trigger only): relative to `base(l)` once voted for `l`, else own final tips. Reader side (binding): only against `beta_v`; before `beta_v` is defined a vote binds only by being final or declaring the chain. | Settledness can wait for the finals on a chain whose capped votes arrived early; the specification's "either way" reading lets a lagging reader settle a chain too early. | I-8, I-PD-20 |
| Grace `t_grace` (L2359-2377, L2528-2544) | Range `[2.5 delta_hat, 2 t_max]` (the specification caps it at `2 Delta`); doubled once per view by a late valid proposal, halved only by a vote for a leader block. | No configured `Delta`; `2 t_max >= 4 delta_hat`, so the range is never empty; the late final for a designated block does not halve it. | I-10, I-A12, I-A13, I-PTB2 |
| Delay `delta` (L150-182, L2213-2228) | `delta_hat = (RTT - eta) / 2` for `RTT` the 90th percentile of recent own-block round trips to the arrival at this node of the `(n - f)`-th endorser's vote, at least `delta_min`, behind a `DeltaEstimator` trait. | Available at every validator, independent of the leader; the endorser's wait for its next update is not delay. Ending the sample at network arrival keeps this node's queueing out of every timer: under saturation the processing-time sample tracked the local backlog (1.3-2.5 s against a 0.1 s network delay at `n = 50`). | D9, D24 in DECISIONS, I-PTB4 |
| Production interval `theta` (L150-182, L2229-2258) | The pace `theta` is the configured constant `Tuning::production_interval` (default 23 ms). `theta_hat` is measured: the upper median across chains of each chain's median gap between accepted heights, and it feeds the timers only. | A constant pace is what the specification assumes; measured `theta_hat` is robust while fewer than half of the chains are faulty. | D9, D22, I-PTB3, I-V4 |
| `t_max`, `t_quiet` (L157-178, L2403-2411, L2518-2527; v2 L193, L196) | `t_max = N theta_hat + 2 delta_hat + eta`, the second version's value (the first has `2 N theta`); `t_quiet = 2 delta_hat + eta` (the specification has `2 delta`). Every timer is capped at `Tuning::timer_ceiling`. | `t_max` is a backstop behind rule (ii); `t_quiet` must exceed `eta + delta` also when `delta < eta` (L2408). | I-PTA5, I-PTB1, I-V2 |
| V-QC size (L545-640) | V-QCs travel in full form; an assembler swaps out the costliest votes while the encoding exceeds `max_vqc_bytes`. | The compact form is not implemented. | I-6, I-A20 |
| Votes not capped (L361-365) | Tips more than `D + 2N` above `max(h*, finalized)` are not resolved; such a vote endorses nothing on that chain and cannot be recorded in a V-QC. | Safe if a correct voter's tip lead stays within `D + 2N` (PO-9, argued from the acceptance bound). | I-6, I-F4, I-PTA2 |
| Header retention (implicit, L473-476, L531-537, L603-616) | Headers of every branch within the band are held, and fetched from peers when a vote names them,; a tip resolves only when its held ancestry links to an accepted header, the origin, or the floor. | One equivocating producer splitting the correct nodes no longer stalls V-QC assembly. | I-PD-21 |
| Unresolvable tips (L486-504, L757-805) | A tip outside the band or on a peer's copy of the own chain endorses nothing toward `Tips` and `b*`, counts as beyond `b*` for `gamma`, and makes `Det` undefined for that vote. | Faulty senders cannot block a reader's queue for their tag. | I-F1 |
| Case (a) (L757-805) | A view is pinned only once an L-QC of a later view is held. If case (a) and case (b) both fix a view and disagree, the step fails. | A node that read votes for `l` only inside V-QCs waits for case (b) or a later L-QC. | I-A21, I-A22, I-A23 |
| Pool retention (L676-690, L2112) | Per-tag endorser partitions; tags retire once the view resolves and leaves `[v - W_back, v + 2]`; durable state retires `W` views below the newest finalized view. | Bounded state; a finality stall stops retention (bounded by capacity, not live). | I-7, I-A26 |
| Accountability (not in the specification) | Objective equivocation quarantines the signer once: two finals of one tag, votes for two leader blocks of one tag, two non-final votes of one tag neither below the other, a vote above its signer's final, two headers at one height, two leader blocks for one view. | Omission and timing are never punished. | DECISIONS |
| Part II (L2555-3235) | Out of scope except the finality evidence above and the epoch field in every signed object; genesis is `H(GENESIS, epoch, i)` from the start. | Lanes, committee change, acknowledgements, payments, fences, and handoff are not implemented. | I-16 |

## Limits of the evidence

- Liveness (PO-15) and fork liveness (PO-22) are exercised by clusters, world, twins, and fuzz
  schedules, not proved. The world has no per-node pause, so anchoring is exercised only by machine
  tests and one cluster test (I-A34).
- PO-9 is argued from the acceptance bound, not proved; the band still enforces it.
- Retention stops when finality stalls; durable state then grows until capacity parks the
  components.
- Codec conformance fixtures (`consensus/conformance.toml`) still list old-protocol types and have
  not been regenerated for the counted-views formats, including `Change::Anchored` and the
  snapshot's `origin`, `ancestors`, and `anchored_tag` (I-A37).
- Most machine tests use symbolic build, custody, and aggregation; the world, twins, and clusters
  use real signatures.
- Accountability is best effort (I-A28): a conflict with a statement the index no longer holds goes
  unnoticed.

## Keeping this document current

`just check-properties`, part of `just lint`, fails when a test cited in a code span as
`multimmit::...` no longer exists. It checks names only: whoever cites a test must make sure it runs
the production code named and asserts the stated property. New invariants go in
`STATE_MACHINE.md`'s table first, then in the evidence table here.
